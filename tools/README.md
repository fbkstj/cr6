# 影片處理腳本使用說明

主辦方收到學生影片後，在自己的電腦上執行這支腳本：檢查影片 → 轉成網頁播放版 → 更新影片清單。
需要 Python 3 與 ffmpeg（`ffmpeg -version` 能執行）。

## 一、放影片

把學生交來的檔案放進專案資料夾的 `影片原檔/`，**依規則改檔名**：

| 情況 | 檔名 |
|---|---|
| 第 1 組第一次交件 | `team01_v1.mov`（或 `.mp4`） |
| 第 1 組補件 | `team01_v2.mov`（版本號加 1，**不要覆蓋舊檔**） |

`影片原檔/` 不會被推上 GitHub（已列在 .gitignore）。

## 二、執行

在專案資料夾執行：

```
python tools/process_videos.py
```

| 選項 | 用途 |
|---|---|
| `--check-only` | 只檢查，不轉檔、不改清單（先看看有沒有不合格的） |
| `--only team01` | 只處理某一組 |
| `--no-limits` | 測試模式：超過 500 MB 或 10:00 不擋，照樣轉檔，清單註記「測試模式未擋」。很長的影片會自動降解析度（15 分鐘 720p、30 分鐘 480p），播放版仍控制在 75 MB 內；約 60 分鐘以上裝不下會報錯。正式比賽不要用 |

轉檔時間大約是影片長度的 0.5～1 倍（10 分鐘影片約 5～10 分鐘，依電腦速度而定）。中途中斷沒關係，已處理完的會記在清單裡，重跑會從沒處理的繼續。

## 三、看報告

| 結果 | 意思 | 要做什麼 |
|---|---|---|
| 完成 | 檢查合格、已產生播放版 | 無 |
| 不合格 | 檢查沒過（原因寫在後面） | 通知該組重交，存成下一個版本號 |
| 略過 | 已經處理過，或檔名不符規則 | 檔名不符的請改名 |
| 錯誤 | 同一個版本號換了不同的檔案 | 補件請用新的版本號 |

**檢查項目**：實際格式是 MP4／MOV、有影像也有聲音、長度不超過 10:00（剛好 10:00 可以）、原檔不超過 500 MB、整支影片可以完整解碼。

**播放版**：H.264＋AAC 的 MP4，**保留原檔解析度（最高 1080p，不放大）**、直式影片自動轉正、保留原本的播放速度與音畫同步，**每支 75 MB 以內**。只有影片很長、碼率不夠時才降解析度（10 分鐘以內都維持 1080p）。

## 四、推上網站並同步

1. 確認報告沒問題後推送（推送等於公開發布）：

   ```
   git add docs/videos
   git commit -m "新增影片：team01_v1、team02_v1"
   git push
   ```

2. 等 1～2 分鐘網站更新，到後台按「**同步影片清單**」，新版本就會出現在作品頁。

## AI 評分（在主辦方電腦上執行）：tools/ai_score.mjs

後台「AI 評分」分頁的按鈕是請伺服器去呼叫 Gemini；免費方案常常太慢或失敗，伺服器又有時間上限（約 150 秒）。
這支程式改在你的電腦上直接等 Gemini 寫完（沒有時間限制），結果送回評分系統，伺服器用同樣的規則驗證並送出到 AI 評審席位。

**需要**：Node.js、在專案資料夾執行、正式系統在「評分」或「結算」階段、競賽有開啟 AI 評審。

```
node tools/ai_score.mjs --all
```

1. 輸入主辦人員帳號（直接按 Enter＝admin01）與密碼。
2. 輸入 Gemini API 金鑰（從 AI Studio 複製，貼上後按 Enter）。**密碼與金鑰輸入時都不會顯示，也不會存進任何檔案**。
3. 程式會一件一件評：上傳影片 → 等 Gemini 處理 → 請 AI 評分（一件可能要幾分鐘）→ 送回系統。最後列出每件的結果。
4. 到後台「AI 評分」分頁看詳情（會標「主辦方電腦」）。「需要處理」的作品可以補分，或再跑一次。

其他用法：

| 指令 | 用途 |
|---|---|
| `node tools/ai_score.mjs team01` | 只評 team01（可以列好幾組） |
| `node tools/ai_score.mjs team01 --rerun` | 已經有 AI 評分也重新評（新結果驗證通過才取代舊的） |
| `node tools/ai_score.mjs --all --model gemini-4-neon` | 換模型（免費方案沒有 gemini-4-neon 的額度） |
| `node tools/ai_score.mjs --all --fake --api http://localhost:8790/api` | 不呼叫 Gemini 的演練（搭配 `node test/devserver.mjs`） |

影片從 `docs/videos/` 讀取（和網站上的是同一份）；本機沒有時才從網站下載。

## 匯入 AI 評分 JSON：tools/import_ai_json.mjs

AI 評分如果不是程式呼叫 Gemini 得到的（例如在 Gemini 網頁版或別的工具評完，結果存成檔案），用這支把檔案送進評分系統。伺服器用和後台一樣的規則驗證（分數整數且不超過滿分、時間點在影片長度內、評語字數），通過就送出到 AI 評審席位，並記錄來源是「人工匯入」。

檔案放在 `AI評分結果/team01.json`…（這個資料夾在 `.gitignore`，不會推上公開 repo）。作品分專題組與創意組，各有自己的評分表（項目與配分不同），檔案的 `items` 要依該作品所屬組別的評分表。格式：

```
{"items":[{"no":1,"score":整數,"reason":"理由","evidence":[{"time":"分:秒","note":"說明"}]}, …共四項],
 "strengths":"作品優點","improvements":"改進建議"}
```

以底線開頭的欄位（例如 `_source`）只是備註，會被忽略。

```
node tools/import_ai_json.mjs --all
```

1. 輸入主辦人員帳號（直接按 Enter＝admin01）與密碼（不顯示、不存檔）。
2. 程式先列出每件要匯入的分數，**輸入 y 才會寫入**。
3. 需要正式系統在「評分」或「結算」階段、競賽有開啟 AI 評審。

| 指令 | 用途 |
|---|---|
| `node tools/import_ai_json.mjs team01` | 只匯入 team01（可以列好幾組） |
| `node tools/import_ai_json.mjs --all --rerun` | 已經有 AI 評分也取代（舊的留在更正歷程） |
| `node tools/import_ai_json.mjs --all --draft` | 只「暫存」：先存起來看，不計入平均；到後台「AI 評分」分頁按「採用」才算數 |
| `--dir 資料夾`、`--label 名稱` | 換檔案資料夾；改記在紀錄裡的來源名稱 |
| `--yes` | 不再詢問直接寫入（演練用） |

## 測試

`python test/test_videos.py`：用合成測試片驗證全部檢查規則、直式影片、音畫同步與碼率上限（約 5 分鐘）。
