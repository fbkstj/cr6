# 影片處理腳本使用說明

主辦方收到學生影片後，在自己的電腦上執行這支腳本：檢查影片 → 轉成網頁播放版 → 更新影片清單。
需要 Python 3 與 ffmpeg（`ffmpeg -version` 能執行；沒有的話 `winget install --id Gyan.FFmpeg --exact --source winget`）。

**平常直接雙擊專案資料夾的 `轉檔.bat`**：[1] 只檢查、[2] 轉檔（完成後列出 `videos/` 的變更，問「確定要推送到網站嗎？」，按 Y 才推送＝公開）、[3] 只推送。推送後等 1～2 分鐘，到後台「競賽階段」按「同步影片清單」：清單裡還沒建立的組別會列出來（作品名稱、組別自動帶入），按「建立組別並同步」。

## 一、放影片

**做法 A（建議，2026-11-23 起）**：照學生交件的樣子放，不用改檔名。`影片原檔/` 底下任何一層的「專題組」「創意組」資料夾：

| 情況 | 檔名 | 組別代碼 |
|---|---|---|
| 專題組第 1 件 | `專題組/專1_作品名稱.mp4`（或 `.mov`） | `team01` |
| 創意組第 3 件 | `創意組/創3_作品名稱.mov` | `team53`（創N＝team(50+N)） |
| 補件 | 同一個資料夾再放一支 `專1_作品名稱_補件.mp4` | 自動成為下一個版本（`team01_v2`） |
| 不要用的檔案 | 移到別的資料夾（例如「不使用」） | 不處理 |

作品名稱取自檔名（底線換成空白、去掉雲端硬碟重複下載加的「(1)」），組別取自資料夾，寫進清單讓後台自動帶入。同一組這次有兩支不同的新檔案會報「錯誤」並都不處理，請只留一支。

**做法 B（舊規則，仍可用）**：`影片原檔/` 最上層改名成 `team01_v1.mov`、補件 `team01_v2.mov`（版本號加 1，**不要覆蓋舊檔**）；這種沒有作品名稱與組別，建立組別時要自己填。

`影片原檔/` 不會被推上 GitHub（已列在 .gitignore）。

## 二、執行

在專案資料夾執行：

```
python tools/process_videos.py
```

| 選項 | 用途 |
|---|---|
| `--check-only` | 只檢查，不轉檔、不改清單（先看看有沒有不合格的） |
| `--only team01` | 只處理某一組 |
| `--no-limits` | 測試模式：超過容量上限（與設定的長度上限）不擋，照樣轉檔，清單註記「測試模式未擋」 |

轉檔時間大約是影片長度的 0.5～1 倍（10 分鐘影片約 5～10 分鐘，依電腦速度而定）。中途中斷沒關係，已處理完的會記在清單裡，重跑會從沒處理的繼續。

## 三、看報告

| 結果 | 意思 | 要做什麼 |
|---|---|---|
| 完成 | 檢查合格、已產生播放版 | 無 |
| 不合格 | 檢查沒過（原因寫在後面） | 通知該組重交，存成下一個版本號 |
| 略過 | 已經處理過，或檔名不符規則 | 檔名不符的請改名 |
| 錯誤 | 同一個版本號換了不同的檔案 | 補件請用新的版本號 |

**檢查項目**：實際格式是 MP4／MOV、有影像也有聲音、原檔不超過 3 GB、整支影片可以完整解碼。**不限長度**（老師 2026-11-23 取消 10:00 限制；腳本裡 `MAX_DURATION_SEC` 設成秒數即可恢復）。很長的影片會自動降解析度讓播放版維持 75 MB 內：約 10 分鐘以內 1080p、約 10～18 分鐘 720p、更長 480p；約 60 分鐘以上裝不下會報錯。

**播放版**：H.264＋AAC 的 MP4，**保留原檔解析度（最高 1080p，不放大）**、直式影片自動轉正、保留原本的播放速度與音畫同步，**每支 75 MB 以內**。只有影片很長、碼率不夠時才降解析度（10 分鐘以內都維持 1080p）。

## 四、推上網站並同步

1. 確認報告沒問題後推送（推送等於公開發布）：

   ```
   git add videos
   git commit -m "新增影片：team01_v1、team02_v1"
   git push
   ```

2. 等 1～2 分鐘網站更新，到後台按「**同步影片清單**」，新版本就會出現在作品頁。

## 匯入 AI 評分 JSON：tools/import_ai_json.mjs

本系統**不呼叫任何 AI**：AI 評分一律在系統外用外部 AI（ChatGPT、Gemini 網頁版等）評完，結果存成檔案。平常用後台「AI 評分」分頁的「匯入 AI 評分檔」；要用命令列批次匯入時，用這支把檔案送進評分系統。伺服器用和後台一樣的規則驗證（分數整數且不超過滿分、時間點在影片長度內、評語字數），通過就送出到 AI 評審席位，並記錄來源是「外部 AI（匯入檔案）」。

檔案放在 `AI評分結果/team01.json`…（這個資料夾在 `.gitignore`，不會推上公開 repo）。作品分專題組與創意組，各有自己的評分表（項目與配分不同），檔案的 `items` 要依該作品所屬組別的評分表。格式：

```
{"items":[{"no":1,"score":整數,"reason":"理由","evidence":[{"time":"分:秒","note":"說明"}]}, …共四項],
 "strengths":"作品優點","improvements":"改進建議"}
```

以底線開頭的欄位（例如 `_source`）只是備註，會被忽略。

**合併檔**：專題組、創意組的 AI 評分可以合併成**一個檔案**一次匯入（後台「匯入 AI 評分檔」、命令列都支援）。三種寫法任選一種：

```
{"team01":{"items":[…],"strengths":"…","improvements":"…"}, "team04":{…}, …}      ← 以組別代碼當欄位
{"teams":{"team01":{…}, "team04":{…}}}   或   {"teams":[{"team":"team01",…}]}
[{"team":"team01","items":[…],…}, {"team":"team04",…}]                       ← 陣列
{"generated_at":"…","專題組":[{"team":"team01","category":"專題組","title":"…","video":"…","total":75,"result":{"items":[…],"strengths":"…","improvements":"…"}}, …],"創意組":[…]}   ← 後台「複製 AI 評分提示詞」請外部 AI 輸出的格式
```

組別代碼是 team01、team02… ；專題組、創意組的作品可以混在同一個檔案裡，系統依各作品的組別用對應的評分表驗證。範例：`AI評分結果/合併輸出/AI評分合併.json`（8 組）。

```
node tools/import_ai_json.mjs --all
```

1. 輸入主辦人員帳號（直接按 Enter＝admin）與密碼（不顯示、不存檔）。
2. 程式先列出每件要匯入的分數，**輸入 y 才會寫入**。
3. 需要正式系統在「評分」或「結算」階段、競賽有開啟 AI 評審。

| 指令 | 用途 |
|---|---|
| `node tools/import_ai_json.mjs team01` | 只匯入 team01（可以列好幾組） |
| `node tools/import_ai_json.mjs --file AI評分結果/合併輸出/AI評分合併.json` | 匯入一個合併檔（也可以是單組檔，`--file` 可以寫多次） |
| `node tools/import_ai_json.mjs --all --rerun` | 已經有 AI 評分也取代（舊的留在更正歷程） |
| `node tools/import_ai_json.mjs --all --draft` | 只「暫存」：先存起來看，不計入平均；到後台「AI 評分」分頁按「採用」才算數 |
| `--dir 資料夾`、`--label 名稱` | 換檔案資料夾；改記在紀錄裡的來源名稱 |
| `--yes` | 不再詢問直接寫入（演練用） |

## 測試

`python test/test_videos.py`：用合成測試片驗證全部檢查規則、直式影片、音畫同步與碼率上限（約 5 分鐘）。
